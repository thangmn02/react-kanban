# Kora design system

Kora uses Astryx Core, the neutral theme and the official project CLI at **0.1.9**. This matches the installed API used for the integration audit. Public Astryx documentation can describe newer releases; use the pinned CLI for exact component contracts. The CLI is a development dependency and is not a production runtime service.

## Discover before implementing

Run these commands from the project root:

```sh
pnpm exec astryx --json doctor
pnpm exec astryx component --list
pnpm exec astryx component Button
pnpm exec astryx docs styling
pnpm exec astryx docs tokens
pnpm exec astryx theme list
pnpm exec astryx template --list
pnpm exec astryx docs migration
```

Check `pnpm exec astryx --help` for supported syntax. Version 0.1.9 covers Tailwind under `docs styling`; it does not accept the newer nested `docs styling-libraries/tailwind` route. Read the exact component's props before using it. Read relevant templates for complex arrangements, then retain only the needed controls. Templates do not authorize replacing Kora's shell.

The managed Astryx block in [AGENTS.md](../AGENTS.md) was generated by the official project initializer. Kora's scope override follows that block. Keep both when refreshing instructions. The project-local setup is sufficient; this CLI version does not expose a user-level installation option. Do not introduce a global dependency or duplicate the CLI's component documentation in a skill.

## Theme, CSS and scope

[AstryxThemeProvider](../src/providers/AstryxThemeProvider.tsx) supplies the prebuilt neutral theme and places theme/mode attributes on `<html>`, so portals share the active tokens. The product uses a light canvas, dark navigation rail, muted context pane and blue actions. The provider supports light/dark/system modes; a fully styled dark product is not currently a supported claim.

[index.css](../src/index.css) declares the layer order before imports: reset, theme, base, Astryx base, Astryx theme, components, utilities. It loads Tailwind, Astryx reset/component CSS, the neutral theme CSS and the app bridge. Do not wrap theme CSS in another layer: the package already owns its layers. Tailwind utilities remain the final override layer.

[astryx-bridge.css](../src/styles/astryx-bridge.css) maps the actual theme's tokens to `--app-*` semantic aliases. Kora keeps its additive radius/spacing aliases. Importing the entire Astryx Tailwind bridge would replace existing Tailwind scales and constitutes a broader migration; it is intentionally excluded. New controls can use documented tokens or the existing semantic aliases without changing unrelated screens.

The shared [Button adapter](../src/components/atoms/Button.tsx) now renders the documented Astryx Button. It preserves the existing text/icon, variants, sizes, disabled state, submit type and callback contract. Its explicit utility classes preserve Kora's visual treatment. Specialized TipTap editing, DnD, native window controls, identity layout, Focus/audio and Beat Grid remain with their existing owners.

## Validation and dependency maintenance

For any shared-control or global CSS change, verify keyboard/disabled/form behavior, portal focus, responsive layouts and reduced motion; inspect Home, Today, tasks, Notes, Focus and the centered identity profile. Use the dedicated browser lifecycle in AGENTS.md. Browser rendering cannot qualify Windows Always on Top, click-through or native lifecycle.

Run focused tests, typecheck, lint, build and bundle checks. `scripts/verify-astryx-surfaces.mjs` records representative screenshots and computed tokens from a supplied built site, then closes its headless browser and loopback server. Keep audit evidence in the owning plan; it is not a substitute for tests or current package contracts.

This repository retains a tracked npm `package-lock.json` while the current workspace runs pnpm. Keep the manifest and tracked lock reproducible when changing dependencies; the ignored pnpm files alone are not clean-clone evidence. Review dependency-only changes separately from CSS and component changes. A future Astryx upgrade must update Core/theme/CLI together only after checking peer compatibility, then rerun the official migration/doctor and affected UI checks.
