# Task workflow and interaction rules

Home presents the first unfinished planned task, falling back to the existing Home service ordering. Its task metadata and Today’s due/priority reasons come from existing services; the interface does not invent personalized AI reasoning. Start Focus retains the existing intention step. Today exposes Focus, completion and planning together, with additional task groups collapsed initially.

Completion from Board, Task Detail, Today and Focus uses one [workflow service](../src/services/task-workflow.service.ts). Canonical ordered To-do / Doing / Done and Backlog / In Progress / Nearly Done / Done boards map completion into Done; dragging into/out of Done completes/reopens. Reopen restores the last valid active location, falling back to the first active column. Other/custom/reordered templates explicitly use completion-only mode without guessing a destination. Status, completion time, membership, positions, one activity and one recurring successor commit together. Reopen never deletes an existing successor. Connected work requires the [transactional RPC migration](../supabase/migrations/20261026163000_task_workflow_transition.sql); local mode writes a recoverable backup before one storage snapshot. Duplicate presses are locked while saving; removal happens only after success. Failures leave the task available to retry. Completed planned tasks retain their existing plan slots and appear as compact finished rows with Remove from Today, preserving the three-slot persistence contract.

Task details use the existing editor as a contextual overlay. The `task` and `taskBoard` query parameters identify the saved task while retaining the originating pathname. Requested boards are checked against the workspace’s boards; the editor waits for a fresh successful snapshot. Obsolete route requests are aborted and older snapshots cannot replace newer ones. Closing removes those parameters. Browser Back closes an opened contextual task. An already-open draft is retained during same-task live updates.

Saved HTTP(S) attachments are available in the editor’s context strip and open in another tab. Starting Focus from the editor requires saved changes, including pending checklist, label and attachment input. Save retains the editor’s existing save-and-close behavior.

Board filters remain in the existing workspace controller. Calendar month/day, Table sorting and route/panel scroll positions are retained in memory for the mounted user/workspace. These UI preferences do not add storage keys or schemas and are not promises of persistence after a full reload. Task and Focus persistence remain owned by the existing services/controllers.

The command palette supports arrow selection, Enter, Escape and contained keyboard focus. Its actions include Home, Today, Board, Calendar, Table and Focus. Focus returns to the command trigger even when a lazy route replaces the header. Lazy route fallbacks stay inside the workspace shell so navigation remains available.

## Motion ownership

Use [shared motion tokens](../src/shared/motion.ts) for finite UI feedback: a short opacity fade, damped layout spring, sortable easing and drop settling. Today animates task position/removal after confirmed saves. Board supports a lifted drag overlay, neighboring sortable movement and authoritative reconciliation after failed optimistic moves. The task grip supports Space/arrows/Space, while blank card content retains existing pointer dragging; list headings remain their drag targets.

Reduced motion disables layout travel and sortable/drop animation. Preserve focus visibility and readable status text. Do not add continuous animation to ordinary task operations. Dock tabs retain mounted panels, the moving indicator and the same host/controller; mode changes receive finite opacity/position feedback. Route loading must not key or remount Focus providers or the Dock host.

P3 exclusively owns Beat renderers, Kinetic/Heartbeat/Exclusive semantics, event timing, capture, detectors and compensation. UX may style the surrounding toolbar and tabs but must not change renderer selectors. Dock base CSS is scoped to `.floating-focus`; the prebuilt Astryx theme keeps its CSS in the base layer so application utilities remain authoritative. See [Focus lifecycle](focus-workflow.md) for playback/PiP ownership.


## Profile and settings

The user avatar opens a centered landscape [employee profile modal](../src/components/layout/identity-card.tsx) over a dimmed, lightly blurred app. Its finite 220 ms reveal uses slight upward translation and scale; exit finishes before removal and focus return. Reduced motion uses an 80 ms opacity reveal. The app stays inert and keyboard focus stays inside the modal through exit. Escape, the close control and backdrop clicks dismiss it; route/account/workspace changes invalidate it. Narrow screens stack the portrait and identity inside a scrollable body while keeping actions visible. The modal renders above app notifications. Long emails retain their full value and accessible text with a two-line display and full title/Settings value. The portrait preserves proportional cover fitting.

Workspace role comes from the active membership. The [read-only activity summary](../src/services/identity-summary.service.ts) loads the account's focus sessions/minutes for today, an exact count of non-archived/non-deleted completed workspace tasks, and its own membership date. Reads are account-fenced; loading/errors use dashes and an unavailable/retry state. Local mode uses existing persisted product activity and does not invent a joined date. Unpersisted job titles or expertise tags are omitted. This adds no account fields, schema, subscriptions or timer/audio owner.

Settings and sign-out wait for profile exit. Settings preserves the existing square crop, drag, reposition, zoom, provider-managed email and language preferences. Light is the supported theme; timer/music settings remain in Focus. PNG/JPEG/WebP inputs are bounded to 5 MB and 40 megapixels; the processed 512px image is at most 512 KB. Cancel leaves the saved profile unchanged. The Kora artwork is the default.

Connected profiles use private, account-prefixed image storage and version-checked profile updates. Apply the [image storage migration](../supabase/migrations/20261026170000_private_profile_images.sql) only after database backup and hosted policy qualification. Shared-workspace members can read the current identity image; other accounts cannot write it. Replacement/reset retires previous owned objects after the profile pointer is confirmed. Failed cleanup is reported and queued for the next save. Logout clears server caches and retains the opaque object-name deletion worklist, durable device Notes originals and scoped Notes drafts. Image retry still requires the same authenticated owner under Storage RLS. Local personalization stays on this device and uses the existing user-scoped storage namespace. Stable assignee IDs remain authoritative; display projection does not rewrite another member or historical task assignments.

## Historical consistency audit

Run `node scripts/audit-task-workflow.mjs snapshot.json` with exported `lists` and `tasks` rows. The tool emits counts and before/proposed metadata only, including expected update versions. It never connects to a database or executes repairs. Keep snapshots/previews private. Missing lists, ambiguous status intent and historical timestamps require an explicit review decision; do not infer past completion times or automatically repair existing user data.

Integration builds do not authorize release. P3 remains qualified only within its tested presentation scope; P4 Engineering is PARTIAL and Production Release is BLOCKED pending combined hosted/native/physical qualification.

## Layered workspace and Notes preview

The desktop shell uses a 56px dark global rail, a 240px contextual sidebar and the existing page canvas. The sidebar collapses to 40px and minimizes automatically on Focus routes. Board context reuses the current workspace's board/list/filter state; Today links to priorities and planning; Workspace opens the existing member/invitation experience. Tablet and mobile keep primary navigation in the header and expose context through an expandable row. No additional timer, theme or audio provider owns this shell.

`/notes` organizes originals, search, Trash/Restore, selected import/export and recovery. Quick Notes opens from the app header, command palette, task drawer, Focus or Ctrl+Alt+N without navigating to the manager. Connected environments opt in with `VITE_ENABLE_NOTES_PREVIEW=true` after the Notes migrations are applied and qualified. Existing TipTap documents, checklists and task links retain their format.

The [device store](../src/features/notes/notes-store.ts) commits browser canonical notes, compare-and-swap revisions and before-image history through IndexedDB transactions. The transactional outbox is authoritative; localStorage is an adoption/compatibility mirror. Windows uses actor-scoped DPAPI journals and atomic, flushed file replacement before a local acknowledgement. Image bytes remain in the existing scoped media repository. A failed local transaction does not display a saved acknowledgement. Same-note history restore uses current revisions and preserves the current version as another before-image.

Connected notes default private in either the workspace or Personal destination. Workspace visibility is explicit; current members can read, workspace editors can edit, and viewers remain read-only unless explicitly granted comment/edit access. Only the note owner manages sharing, deletion and restoration. Explicit grants require current membership and are retired when membership is removed. Rejoining does not revive old grants. Removing an owner does not transfer ownership: workspace-visible content stays visible and the owner must be readmitted to manage it. The member-removal confirmation explains this boundary.

The [connected session](../src/features/notes/connected-notes-session.ts) persists account/destination drafts before a bounded debounced save, checks revision and write identity, retains failed writes, and fences account changes. Conflicts require reviewing the server version, resuming a matching draft, saving a separate copy, exporting, or explicitly discarding the device draft. Documents and drafts survive logout without becoming visible to another signed-in account. Import is an explicit private copy; retries preserve remote content and complete missing per-user layout without overwriting an existing layout. Local originals are retained.

Layout, pins and minimized/expanded state belong to each user. Dragging a grip left/right repeatedly activates Peek; the button provides the same action. Peek stays ephemeral, transparent, inert and pointer-transparent until restored. It never changes resource access. Notes provide shared/recent/pinned/search and owner Trash/Restore views, comments with author/owner editing, and current-member sharing controls. Task notes open above the task editor so its unsaved fields and page remain mounted. Today can create a note, and Focus exposes pinned Notes without replacing the timer owner. Whole-note and selected-text conversion use stable task identities for safe retries; original note content remains available.

See [connected qualification and recovery](connected-qualification.md) for local backup/restore, migration preparation, actual authenticated checks and hosted gates.

## Saved Context and external notes

Saved Context stores only the current actor, source type and original ID. Supported sources are tasks, task comments, notes and note comments. Previews and Open original resolve current access; archived, deleted or revoked sources do not retain readable previews. Stale references can still be removed. Minimal task comments provide author/admin editing, deletion and Save/Open original without introducing a chat system. Notes pins and saved note references stay consistent; references never become duplicate note content.

On Windows, Float outside Kora opens a registered Tauri note window backed by the same main repository. Its WebView receives a scoped document and media through the broker, without a Supabase session, Focus owner or broad native filesystem permissions. Always on Top, opacity and expanded/bubble bounds are per-device. Ghost uses actual native click-through; the tray and Notes Manager provide independent Restore actions. Hidden and collapsed windows remain separate from Trash.

The tray can create a Quick Note or restore notes while the main window is minimized. Global capture is opt-in through Windows Quick Notes in the manager; registration conflicts leave the app shortcut and tray available. Quit, sign-out and user workspace changes prepare all external frames and wait for acknowledged local durability. Frames freeze during that handshake and become editable again if the transition is canceled. Account/workspace changes destroy stale native windows and subscriptions. Restart reopens the scoped catalog after current access is checked; unavailable connected originals wait for revalidation while their durable drafts remain recoverable.
